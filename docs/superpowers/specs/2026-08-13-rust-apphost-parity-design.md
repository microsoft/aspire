# Rust AppHost parity

## Goal

Rust AppHosts should have the same Aspire workflow as C# and TypeScript AppHosts wherever the language can support the same contract. This includes editor features, source navigation, Run/Debug, runtime argument forwarding, and language telemetry.

## Scope

This change adds the missing Rust behavior in four places:

- CodeLens and gutter resource-state decorations in `apphost.rs`.
- A generated project layout where `apphost.rs` is the executable source file.
- Correct Aspire argument forwarding through `cargo run --`.
- Rust language and target-version telemetry.

Rust hot reload is not part of this change. Cargo has no built-in watch command, and adding an external watcher would create a separate install and lifecycle contract. rust-analyzer language features are also owned by the Rust extension rather than Aspire.

## Editor parser

The existing CodeLens and gutter providers share `AppHostResourceParser`. A new self-registering Rust parser will implement that interface and add `rust` to the document selector generated by `getSupportedLanguageIds()`.

The parser will use `tree-sitter-rust` through the extension's existing `web-tree-sitter` infrastructure. Version 0.24.0 and its runtime dependencies are mirrored in the approved `dotnet-public-npm` feed. The parser will walk Rust syntax nodes to:

- Detect an AppHost from a real `create_builder(...)` call.
- Find `add_*` calls whose first argument is a closed string literal.
- Treat `add_step` as a pipeline step.
- Find the statement containing `create_builder(...)` for AppHost-level CodeLens.
- Ignore markers inside comments, ordinary strings, raw strings, and malformed calls.
- Preserve source ranges and statement start lines for fluent chains.

The grammar handles Rust comments, strings, raw strings, malformed input, and statement boundaries. The Aspire parser remains focused on AppHost calls and keeps the same parser contract as C# and TypeScript.

## Cargo diagnostics

`cargo metadata` receives the resolved resource environment, so its stderr can echo secrets supplied through environment variables. Persistent exceptions will redact every nonempty resource environment value from stderr, matching longer values first, and then truncate the redacted diagnostic to 4 KiB. Redaction happens before truncation so a secret crossing the truncation boundary cannot leak a partial value.

## Generated layout

Generated Rust AppHosts currently put executable code in `src/main.rs` and leave `apphost.rs` as a marker. That makes the discovered AppHost file different from the file users edit, debug, and navigate to.

The scaffold will instead write executable code to `apphost.rs` and add a Cargo `[[bin]]` entry with `path = "apphost.rs"`. The module path becomes `.aspire/modules/mod.rs`. This matches the existing Rust playground and lets discovery, source navigation, CodeLens, gutter state, and debugging all use one canonical file without Rust-specific aliases in the extension.

## Runtime invocation

Aspire appends operation arguments such as `--operation publish` to guest runtime commands. Cargo interprets those as its own flags unless the command includes an argument separator. Rust execution will use `cargo run --`, allowing Aspire arguments to reach the AppHost binary in run and publish flows.

The existing watch fallback remains unchanged. It invokes the same corrected execute command when no language-specific watch command exists.

## Telemetry

Rust becomes a first-class language family alongside C# and TypeScript. Candidate summaries, direct file classification, directory classification, and debug-session telemetry will report `rust`. Mixed Rust and another family will report `polyglot`.

Direct `apphost.rs` target-version lookup will use the adjacent `aspire.config.json`, matching TypeScript guest AppHosts.

## Validation

Focused validation will cover:

- Rust parser detection, resources, pipeline steps, ranges, chains, comments, strings, raw strings, and malformed input.
- Parser registry, CodeLens, gutter, and AppHost file-presence behavior for Rust.
- Rust language and target-version classification.
- Generated file set, executable `apphost.rs`, Cargo binary path, and runtime separator.
- Existing Rust code-generation and Cargo metadata tests.
- Extension lint, compile, and focused unit tests.

A final extension build with the local CLI will verify the extension/CLI contract together.
